# The full agentic CLI

Four steps in this pipeline ask a model something: the **planner** turns a prompt into a brief,
the **executor** writes the sketch, the **judge** compares two finished entries, the **critic**
writes the sentence that becomes the next prompt. All four run on the node's own models today.
This document is how a model that is *not* on the node comes to run any of them — assigned per
job or per step, driven from the CLI by an agent on a machine that holds the credential.

It is not four new pipelines. It is one envelope, four adapters, two schema changes and one
decision about what the gallery says about itself. §2 is the argument for why it is that small;
§1 is the constraint that makes §0's decision unavoidable before the executor ships.

Five packets, one branch per packet, one PR each (§4). It touches `sketchgen/judge.py` (as the
source of the pattern, not to change it), `sketchgen/paid.py` (new), `sketchgen/cli/paid.py`
(new), `bin/sketchgen`, `sketchgen/db.py`, `sketchgen/models.py`, `sketchgen/web.py`,
`sketchgen/worker.py`, one migration, the templates that carry the AI disclosure, and their
tests. **No change to `writepath/`, `sync.py`, `gallery.py`'s layout, or any prompt file.**

Read `docs/plans/lineage-ledger.md` for the packet conventions and
`sketchgen/judge.py` §"The paid judge, branch B" for the pattern being generalised.
`python3 -m unittest`, no pytest, stdlib only, in both halves.

## 0. What the repository says today

The four steps are at four different stages, and the distance between them is the work.

| step | its model | paid route | where it is |
| --- | --- | --- | --- |
| **judge** | `SKETCHGEN_JUDGE_MODEL`, `gemma4:e4b` | **built end to end** | `judge.py:692` `export_claims`, `:740` `claims_packet`, `:788` `import_verdicts_detailed`; `cli/judge.py:225,249` |
| **planner** | `SKETCHGEN_PLANNER_MODEL`, `gemma4:e4b` | half built | out: `worker.py:2126` parks the job; back: `plan --job` (#119). No packet, and the New job menu cannot name a paid model |
| **critic** | `SKETCHGEN_CRITIC_MODEL`, `gemma4:e4b` (`worker.py:245`) | **none** | `lineage.py:552` renders the prompt, `:588` validates the answer, `:635` calls the model. Nothing separates the two halves |
| **executor** | `jobs.executor`, `qwen3-coder:30b-a3b-q4_K_M` | **none** | `needs` has no `execute` (`migrations/001_init.sql:33`), and `executing` cannot reach `needs-laptop` (`db.py` TRANSITIONS) |

The rule all four live under is DECIDE[credential-model] branch B, spec §6: **the paid model never
runs on the node.** The node has no key and is not getting one. So a paid step is always two legs —
the node writes down what it would have asked, something that holds the credential answers, the
node reads the answer back — and the whole of this document is about making those two legs cheap
enough to drive from a shell.

## 1. The constraint nobody has costed yet

Every public page carries this, and the README says it too:

> **AI Disclosure:** All code is generated by sketchgen from its own database of human and
> agent-generated prompts using **fully attributed self-hosted models on traceable compute**.

`templates/grid.html:44`, `entry.html:86`, `compare.html:63`; the tagline above it says *running
self-hosted models*; `README.md:125` says `API calls | 0 — all inference local`.

A paid **executor** writes code. Ship it and that sentence is false on every page of a gallery
whose whole claim is that it is traceable. The planner writes a brief and the judge writes a
verdict, so neither touches the word *code* — but the tagline's *self-critiquing … self-hosted*
is dented by a paid critic, and `0 API calls` is falsified by any of the four.

`docs/OPERATIONS.md` already concedes half of this — *"the gallery's '0 API calls' is true of the
first group only"* — in a table nobody reading the gallery will ever see.

**This is fixable rather than fatal, and the fix is already half-built.** Provenance is per entry:
`entries.planner` and `entries.executor` hold model ids, and they are honest today. Entry 1223,
made while testing #119, reads `planner = claude-sonnet-5`, `executor = qwen3-coder:30b-a3b-q4_K_M`
— the first entry in the gallery whose brief came from off the node, and the row already says so.
So the disclosure can be made *accurate* instead of being abandoned or quietly broken.

It is Packet 0 because it gates Packet 4 and costs a morning.

## 2. Why this is smaller than it looks

Every one of the four steps is **already split down the middle**, because the stub path exists for
testing and the stub path is exactly the seam a paid model needs:

| step | renders its own prompt | parses a reply from anyone | replays a saved one |
| --- | --- | --- | --- |
| planner | `planner.build_prompt` | `planner.parse_response`, `recover` | `plan --stub` |
| executor | `executor.render_prompt:252` | `executor.parse_response:305` | `execute --stub` |
| judge | `judge.build_prompt` | answer validation, `import_verdicts` | `judge import` |
| critic | `lineage.critique_prompt:552` | `lineage.validate:588` | `lineage critique --stub` |

Neither half knows or cares which model produced the text in between. That is not an accident of
this codebase, it is its house style — *"nothing here calls a model"* is asserted at the top of
half the test files — and it is why the planner's return leg in #119 came to about 150 lines: the
parser was already shared, so the only new code was *read the job, write the answer back where the
worker writes it.*

So the shape of every packet below is the same, and only the middle column differs:

    export  →  render the prompt the local path would have rendered, plus its inputs and a guard
    (laptop →  an agent answers each item with the model that holds the credential)
    import  →  parse with the parser the local path uses, write where the local path writes

## 3. Decisions

### 3.1 One envelope, four adapters — recommended

`judge.py`'s packet is the design: an envelope naming the kind, the model it was cut for, the
prompt version and the time; a list of items; each item carrying the rendered prompt, the inputs,
**paths** to any images rather than the bytes, a guard hash, and an empty answer slot. Generalise
it into `sketchgen/paid.py` with a `step` field, and give each step an adapter of about forty
lines that knows three things: what to offer, how to render, where to write.

`judge export` / `judge import` stay as they are and become aliases. Packets already written must
keep importing — `PACKET_KIND = "sketchgen-judge-claims"` is on disk in files this project has
already produced.

### 3.2 Images travel as paths, never as bytes — settled, inherited

The judge decided this and it was right: *"the laptop reads the images itself, over scp or the
tunnel — the bytes are not copied into the packet, which keeps a packet small and keeps one copy
of the artefact."* The critic needs the same (one strip, not two). A packet stays a text file
small enough to paste.

### 3.3 Every item carries a guard, and the guard differs per step

A verdict is only interpretable against what the model actually saw (spec §5). What can move under
a request is different for each step, so the guard is too:

| step | guard | why |
| --- | --- | --- |
| judge | `pairs.artefact_hash` | both strips and both briefs — already built |
| critic | `entries.strip_sha256` | the strip is the evidence; `lineage.py:44` already refuses to critique blind |
| executor | the previous attempt's evidence digest | attempt *n* is a reply to attempt *n−1*'s gate output |
| planner | **none needed** | `jobs.prompt` is written once by `enqueue` and no code in this repo updates it |

Saying *none needed* out loud matters: it is why #119 has no hash in it, and a reviewer who
expects one should find the reason here rather than deduce it.

### 3.4 The critic's table cannot hold two critics — the one real schema surprise

`judgments` is `UNIQUE (judge_kind, judge_id, entry_a, entry_b, question)`
(`001_init.sql:112`): keyed on **who judged**, so a paid judge and a local judge coexist by
construction, and the two populations are never aggregated (spec §5).

`critiques` is `UNIQUE (entry_id, prompt_version)` (`006_critiques.sql:36`): keyed on **what was
asked**, not who answered. A paid critic and the local critic therefore compete for one row per
entry per prompt version, and whichever runs first locks the other out — silently, because
`entries_to_critique` will simply stop offering that entry.

Three ways out, and this is a decision, not a detail:

1. **`critique_by` joins the key** — a migration rebuilding `critiques`, and every entry becomes
   critiqueable once per critic. Honest, and it doubles the children the idle loop spawns.
2. **The paid critic is the only critic for entries it touches** — an assignment, per §3.6, and
   the local critic skips what is assigned away. No migration. Recommended.
3. **Paid critiques do not spawn children** — they are recorded as commentary and the lineage
   stays local. Cheapest, and it gives up most of the point.

### 3.5 A paid executor is a second variable in a running experiment — flag, do not solve

`OPERATIONS.md` already warns that varying the executor *"puts another difference into the same
gallery … 'recoverable' is not 'controlled'"*, and that is about two local models. The A/B rig
measures the rules file across one population, scored with Bradley–Terry. A paid executor is a
much larger difference than the one the warning is about.

Nothing in this plan should try to fix that. It should make it **visible**: the executor is on
every attempt row and every entry, so the analysis can control for it, and the operator should be
told at the point of assignment rather than in a document.

### 3.6 Assignment: one setting, not four flags — recommended

*"A paid model runs all tasks"* is the ask, and four independent switches is not it.

- `jobs.planner` and `jobs.executor` already carry a model id per job. Keep them.
- judge and critic are node-level (`SKETCHGEN_JUDGE_MODEL`, `SKETCHGEN_CRITIC_MODEL`) because
  they are idle work, not job work. Keep that too.
- Add an **assignment**: a `meta` row naming the model for each of the four steps, which the New
  job page and the idle loop read as their default, and which a job may override for its own two.

`paid` stops being a sentinel and becomes what it always meant: *a model that is not on this node*.
`worker.py:2068` `planner_model_for` keeps treating the literal word as "the worker's default" for
rows written by older pages.

### 3.7 The menus need a source of paid model ids — small, and blocking

`models.py:199` `catalogue` reads Ollama and nothing else, which is why the New job page cannot
offer a paid model. It needs a second source: a list of **names**, configured, with no credential
and no network call — `SKETCHGEN_PAID_MODELS`, or a `meta` row. A name is not a secret, and the
node must not be able to verify it, because verifying it would mean calling it.

### 3.8 What runs the laptop leg — say it plainly

An agent. `sketchgen paid export` writes a file; a coding agent on a machine with a credential
reads it, answers each item with its own model, and hands it back to `sketchgen paid import`. The
credential is the agent's, the node never sees it, and *"agentic CLI"* means precisely that the
verbs are shaped for something other than a person to drive.

The corollary is worth stating because it has already cost us once: an agent driving these verbs
must never be told to make the node act by other means. #118 is the record of what happens when
the return leg is missing and the agent improvises — it reached for a second worker, raced the
daemon, and wedged the node for half an hour. Every verb here exists so that no step of this
requires improvisation.

## 4. The packets

### Packet 0 — what the gallery says about itself

`templates/grid.html`, `entry.html`, `compare.html`, `README.md`, and whatever §3.4's answer
implies. Narrow the gallery-wide claim to what stays true; put the truth per entry where the entry
already knows it; badge an entry any of whose models ran off the node. No Python beyond the
generator strings and their tests.

Blocks Packet 4. Does not block 1, 2 or 3.

### Packet 1 — `sketchgen/paid.py` and `sketchgen paid`

The envelope, the guard protocol, `export` and `import` with the judge's rejection reporting, and
the adapter interface. Port the judge onto it and keep its CLI working. Nothing user-visible
changes in this packet, which is the test: the judge's existing tests pass untouched.

### Packet 2 — the critic

Terminal, so no state machine: the adapter offers what `entries_to_critique` offers, renders
`critique_prompt`, carries the strip path and its sha256, and writes back through
`db.record_critique` and `lineage.spawn` — the two calls the idle loop already makes. Parser is
`lineage.validate`, unchanged, including its rejection rows. Needs §3.4 answered first.

### Packet 3 — the planner, finished

`plan --job` is the return leg already. This packet adds the outbound half so the operator does not
hand-assemble a prompt, and the menu work from §3.7. Smallest of the five.

### Packet 4 — the executor

The one with a migration in it.

- **Migration 014**: widen the `needs` CHECK to include `execute`. SQLite cannot alter a CHECK, so
  `jobs` is rebuilt — `007_states.sql` is the worked example, including why `PRAGMA foreign_keys`
  is off during a migration and why the column order must not change.
- **TRANSITIONS**: `executing -> needs-laptop`. `repairing -> needs-laptop` already exists.
- **The loop: one round trip per attempt, auto-reparked.** `import` writes the sketch into
  `attempt-N/`, the node gates it locally — the gate is the referee and it does not move — and a
  failed gate parks the job straight back at
  `needs-laptop` with the evidence folded into the next packet. The operator repeats two commands
  until `db status` shows the job held.
- **The write-back goes to the queue, not to a running state.** `db.claim_next` selects on
  `state = 'queued'` alone; anything that moves a job into `executing` without then holding it
  leaves it for the stuck-sweep. #119's first draft had exactly that bug, caught before it
  shipped; the same trap is waiting here once per attempt rather than once per job.

### Packet 5 — assignment and the menus

§3.6's `meta` row, the New job page reading it, the idle loop reading it, and the operator being
shown §3.5's warning where the choice is made.

## 5. Acceptance

Per packet, and all of it offline — every test replays a saved reply and calls nothing:

1. A packet cut for each of the four steps round-trips through `import` and lands the same rows the
   local path lands for the same reply. This is the whole plan in one test, four times.
2. A packet whose guard no longer matches is **rejected with a reason and writes nothing** — the
   judge's rule, applied to the strip, the evidence and (not) the prompt.
3. A partially answered packet records the answered items and skips the rest in silence.
4. An unparseable answer leaves the subject exactly where it was: the job parked, the entry
   un-critiqued, the pair unjudged, and the raw text saved.
5. A paid executor's failed gate re-parks the job with the previous attempt's evidence in the next
   packet, and attempt numbering continues rather than restarting.
6. `judge export` / `judge import` still work on a packet written before Packet 1.
7. An entry made by a paid model is badged and its provenance is right on its own page.
8. The local path is untouched: the whole existing suite passes with no edits.

## 6. Running it

    # on the node
    python3 bin/sketchgen paid export --step execute --out packet.json

    # on a machine with a credential — an agent reads, answers, writes back
    #   (the strips it needs are named by path; it fetches them over the tunnel)

    # on the node
    python3 bin/sketchgen paid import packet.json

For a whole job run paid, that pair is repeated per step and, for the executor, per attempt.
Nothing here runs a worker; the node's own daemon does the gating and the publishing as it always
has. **Never run `worker --once` beside it** — the fence refuses that since #118, and this is the
path that made it necessary.

## 7. Effort

Packet 1 is the real one: a day, most of it the guard protocol and getting the judge onto it
without disturbing packets already on disk. Packet 4 is a day for the migration, the loop and
their tests. Packets 0, 2, 3 and 5 are half a day each, and 0 is a morning of prose.

The order is 1 → 2 → 3 → (0) → 4 → 5. Packet 0 can be written at any time but must land before 4.

## 8. Out of scope, and worth a packet later

- **A paid model that also gates.** The gate is the referee: it runs headless Chromium on the node
  against a pinned Playwright, and `requirements.txt` says at length why that pin is what makes
  verdicts comparable. Nothing paid should touch it.
- **Cost accounting.** `billing.py` prices this tenancy's compute. Paid inference is somebody's
  invoice, not Oracle's, and folding it into the same odometer is its own decision.
- **Automating the laptop leg from the node.** The node could hold a queue and an agent could poll
  it, and the moment that exists somebody will run it with a key on the node. Branch B is a rule
  about where credentials live, and convenience is how it erodes.

## 9. Addendum, 2026-09-21: the harness, second pass

Two runs by a Sonnet 5 session after packets 1–5 and #130 landed, and what each
one taught:

- **A blocking `wait` is the wrong shape for an agent.** Its tool call times out
  at ten minutes; the job was queued behind an idle-spawned child whose local
  planner timed out twice. `paid next` replaces it: returns within 240 s with
  the packet, or `wait` and the worker's current step, or `done`/`stop`.
- **The worker did not know an agent was waiting.** It ran the judge, the critic
  and the critic's child between the agent's import and its own claim. A *lease*
  (db.paid_leases) — taken by `start`, renewed by every verb on the job, expiring
  on its own — makes the worker claim the leased job first and do no idle work
  while it is live.
- **A paid job with no agent attached is an orphan.** The page offered `paid` and
  registered ids; `lineage.spawn` inherited a paid parent's models into the
  idle critic's child (job 1252). Both are closed: the page lists what the node
  runs, `assign` refuses a paid plan/execute default, `spawn` blanks a paid
  model, and `paid start` — one verb, from the CLI, by the agent that answers —
  is the only way a paid job is made. `paid release --job N` hands an orphan
  back to the local path.
- **Quoting through ssh is a trap.** `bin/sg` quotes each argument once with
  `printf %q`; stdin and stdout pass through.

§3.8 stands: the laptop leg is an agent at a shell. What changed is that the
node now has a way to know the agent is there.
