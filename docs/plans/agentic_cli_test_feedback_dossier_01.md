# Agentic CLI test feedback — dossier 01

A paid agent drove one job end to end and it went well: one attempt, no repair, no release. The node
saw four and a half minutes of it. The agent spent thirty-seven more before the node knew it existed,
and most of that went on a test rig it had to stand up itself. This dossier records the run, measures
it, and asks for the two things it showed were missing: a rig staged in advance, and a way for the
agent, and the entry, to know what the work cost.

## 1. The finding

The loop is right. `start` to `held` took **4 min 26 s**: a 39 s plan round trip, a 1 min 50 s execute
round trip, and a gate that answered in about five seconds. That is the size of a free-node job.

Everything else happened where the node could not see it. Before `start` the agent spent
**37 min 24 s**, made 109 tool calls (at least 59 of them driving a browser), took 16 screenshots and
generated **192,739 tokens, 77% of them thinking**, to produce a reply of 9,732 characters. Some of
that was the agent's own judgment (§4, rows 5 to 8). Most of the rest was building a way to look at
the sketch and time it, because the CLI offered neither. Nothing told the agent it was spending too
much, and nothing recorded that it had.

## 3. What worked, and should stay

- One shape for the whole job: `start`, `next`, answer, `import`, `next`, `done`. No step needed
  improvisation, and the stop rule never fired.
- `next` told the truth while it waited (*"the worker is on job 1285 (Evaluating the sketch in a
  browser…) and takes yours next"*), so a 70 s wait was legible and the agent left the node alone.
- `bin/sg` took a prompt with spaces and quotes with no second layer of quoting.
- The packet's `model` came pre-filled with the agent's own id. `import` said what had landed in
  plain words. A plan and a sketch each imported first time.
- The gate answered in about five seconds. Attempts are cheap, which matters in §5.
- Nothing was written to the node by hand.

## 5. Finding A: the agent had to stand up a rig

### 5.1 What it built, and the six traps

A static server through a temporary `.claude/launch.json` (the Browser pane cannot script `file://`,
and the file is not gitignored, so it had to be deleted afterwards); p5 1.11.3 fetched from cdnjs; a
harness `index.html`; a lab copy of the sketch with runtime switches and phase timers; a CPU-canvas
benchmark; a robustness probe (0×0, 1×1, portrait, wide, ten rapid clicks, a finite-values check, an
error hook); a synthetic-click helper. Each of these was written from scratch.

1. `file://` pages in the pane are not scriptable. An http origin is needed.
2. A hidden pane runs no `requestAnimationFrame` and reports `windowWidth` 0 at load. An unguarded
   sketch threw NaN every frame and never recovered. The tab has to be selected before anything moves.
3. The pane sits at device pixel ratio 1.75, so p5 uses density 2, and screenshots are downscaled
   device frames. One looked like a bug in the sketch. The gate is DPR 1.
4. **Timing on the pane's GPU canvas is meaningless.** `getImageData` after each frame adds a ~20 ms
   flush floor, and one identical variant read 14.7 ms and then 38 ms. Swapping `drawingContext` for
   an offscreen `willReadFrequently` canvas gave a stable CPU-raster number, and showed that a
   full-canvas gradient backdrop cost 5.7 ms a frame, as much as the whole rope, which the GPU canvas
   had hidden.
5. The console tool keeps errors across reloads, so old errors read as new.
6. A synthetic click dispatched to both the canvas and `window` fires p5's handler twice.

### 5.2 What a rig has to know

All of this is in the repository already; the agent read it from `gate/sketch_gate.py`,
`prompts/executor.md`, `prompts/rules/treatment.md` and `gate/README.md`, which cost a good part of
the first fifteen minutes.

| fact | value | where |
| --- | --- | --- |
| viewport | 1280×900, device pixel ratio 1 | `gate/sketch_gate.py` `VIEWPORT` |
| idle window | 120 stepped frames on a virtual 16.667 ms clock, then one click at the canvas centre, then 30 frames | `IDLE_FRAMES`, `PROBE_FRAMES`, `click_centre` |
| assertions | `motion(idle)` and `responds(click)` pass on any changed pixel | `evaluate_assertion` |
| QA | no console error; the loop keeps advancing; mean wall time per frame ≤ 100 ms (trips early at 2×; 90 s ceiling) | `DEFAULT_FRAME_BUDGET_MS`, `EARLY_TRIP_FACTOR`, `DEFAULT_BUDGET_S` |
| library | p5 1.11.3, in the `index.html` that `sketchgen/executor.py` writes | `executor.py` |
| rules | global mode, `createCanvas(windowWidth, windowHeight)`, ~150 lines, ~2,000 shape calls a frame | `treatment.md`, from the packet |

### 5.3 `paid try`: the rig, on the node — recommended

The node already has everything the agent improvised: the pinned Playwright, headless Chromium with
no GPU, the gate, the `index.html`. What is missing is a verb that lets the agent use them before it
commits.

    bin/sg paid try --job N --as $ME < sketch.js

Runs the real gate on the candidate, in a scratch directory under the job, with the job's assertions.
It writes no attempt, no entry and no row, and it uses no attempt. It returns the checks, each
assertion with its detail, `timings.ms_per_frame`, the console lines, the unreachable `resources`,
and the node path of `strip.png` and `gate.png`, to be fetched with the `scp` the judge and critique
steps already use. One look at a three-frame strip replaces a dozen screenshots.

**Where it runs matters more than what it does.** The worker owns the inference slot, and its
docstring records why: one process on the slot, and idle work scheduled *inside its loop rather than
by a second timer*, because a second client contends for it (the figure it gives is about 9× slower,
for inference). A gate is CPU-bound and measures `ms_per_frame` "on the same machine as the model",
so a second gate beside the worker's would perturb the referee's own number, and could fail an
unrelated job on frame budget. `try` therefore should not be a second process. The CLI writes a
request; the worker serves it between claims; the CLI polls, as `next` does. While a lease is live
the worker is standing by for the agent and starts no idle work, which is exactly when the slot is
free. `DECIDE[try-where]`: in the worker (recommended), or a subprocess from the CLI that refuses
while the worker is gating.

It renews the lease, since it is the agent's activity, and it is capped per job
(`DECIDE[try-budget]`, strawman eight). It is advisory: the gate stays the referee, and a `try`
verdict never lands on an entry. The plan's §8 rule that nothing paid touches the gate is kept; `try`
runs the gate, it does not change it.

Acceptance:

1. Each of `gate/fixtures/*`, submitted through `try`, returns the verdict in `expected.json`.
2. A `try` leaves the database as it found it: no attempt row, no entry, attempt count unchanged.
3. A `try` never overlaps a real gate run.
4. Without a live lease for that agent `try` refuses with exit 3; with one, it renews it.
5. No paid credential anywhere on the node (AGENTS.md rule 2).

Why this is the first-class fix and not the local rig: it is the same gate, so a sketch cannot pass
the rig and fail the referee; it needs no setup; it reports the number that decides the outcome,
where a local proxy can only estimate it; and it moves the work inside the lease, where it is counted.

## 6. Finding B: nothing tracked time or tokens where it counted

### 6.1 What exists since #132

The node times the round trip of each off-node step (`round_trip_s`, export to import) and stores it
as `wall_s`. Token counts go on the attempt only if the agent puts them in the item's `usage`;
otherwise they stay null, never zero. AGENTS.md says the same: *never estimate; a blank on the entry
page is true, a guess is not.* This is the right design for what the node can know.

### 6.2 Why it did not help here

1. **`wall_s` starts at export, and the work started 37 minutes earlier.** Entry 1279 will show a
   1 min 50 s round trip for the sketch. That reads as "the model wrote it in under two minutes",
   and puts it beside a local model's decode time as though they were the same measurement.
2. **`usage` cannot be filled honestly.** It asks for the token counts *of the reply*. The harness
   reports how full the context window is, not what was generated, and gives no per-reply count. Both
   fields stayed null, which was correct, so the entry has a round trip and no counts.
3. **Nothing showed a budget.** `start` prints a lease deadline, which is about inactivity and says
   nothing about effort.
4. **The design pushes work out of sight.** Row 4 of §4.

### 6.3 What can be measured today

Checked in this session, with no change to the repository:

- **Clock.** `date -u`, and `get_session` (`createdAt`). Enough to give every reading an elapsed time.
- **Context.** `get_usage`: `tokensUsed`, with categories. The fixed overhead here is 58,950 tokens
  before any work, so a budget in context tokens has to be about *growth*, not the total.
- **The transcript.** The desktop app writes `~/.claude/projects/<project>/<session>.jsonl`. Each
  assistant message carries its `usage`, including `output_tokens` and, in `output_tokens_details`,
  `thinking_tokens`, and a timestamp. `cost.py` (Appendix) totals them by window and counts tool calls
  and screenshots, and reproduces every figure in §2. This is the missing meter, and it needs nothing
  installed.

What none of them gives is the reply's own `completion_tokens`, which is what `usage` asks for.

### 6.4 Two costs, kept apart

- **Reply cost**: what the node was sent, and how long the round trip took. This is what compares
  with a local model's prompt and decode. It is `usage` and `wall_s`, and it is small: this run's
  reply was a few thousand tokens and under two minutes.
- **Process cost**: everything the agent did around the reply. Session time, tokens generated,
  thinking, tool calls, screenshots, effort, skills. This run's was 42 minutes and about 207,000
  tokens.

The free-node baseline is a reply cost plus the node's own compute. Setting a whole agent session
against it is unfair one way, and setting `wall_s` against it is unfair the other. Record both, show
the process cost beside the entry, and never let it into the A/B measures.

### 6.5 Proposal (Packet 8)

- **`start --since ISO`**: when the task began. AGENTS.md makes the agent's first command
  `date -u +%FT%TZ`, and it passes the result. Stored as `jobs.since_utc`, shown as *declared by the
  agent*. Every `next` and `import` then echoes `elapsed 12m` against the budget below. Harness-agnostic.
- **`process`**, optional beside `usage`, all fields nullable, "as reported by the agent":
  `{session_s, output_tokens, thinking_tokens, tool_calls, screenshots, effort}`. `cost.py` prints the
  line to paste. An agent whose harness cannot report leaves it out.
- **`start --note TEXT`**: free text on the job and the entry: `skill=algorithmic-art; local
  prototype`. The node cannot see what the agent did around the reply. `migrations/012_harness_version.sql`
  made this argument about the referee: what judged an entry was not recorded, so a comparison across
  the change would read one distribution as two. Entry 1279 differs from a plain paid run in exactly
  the way the node cannot see.
- **A budget line** in `start`'s output, so the agent has a number to hold itself to
  (`DECIDE[agent-budget]`; strawman: held within 10 min of `--since`, under 30,000 tokens generated;
  this run's job phase alone was 4 min 26 s and 14,798).
- **An AGENTS.md note**, in Packet 6:

  > **Budget.** Your first command is `date -u +%FT%TZ`; pass it as `--since`. A sketch is a few
  > minutes' work: read this file, plan, write under 150 lines, `paid try`, import. The prompt says
  > "no second chance". That is written for local models. You have three attempts and a verdict takes
  > seconds. If your harness reports elapsed time or context size, put them in `process`. If not,
  > leave it out.

## 7. Smaller findings

1. **The read-first instruction is only as good as the checkout.** The agent read AGENTS.md at #131.
   The node's packets carried the `usage` slot that #132 added. Nothing said the two differed, and
   `bin/sg` never checks. `DECIDE[freshness]`: `paid start` prints the node's deployed commit, and
   `bin/sg` warns on stderr when that commit is not in the local history.
2. **`done` says only `held as entry N`.** `held` is reached by a clean pass and by an assertion missed
   after the attempts are spent (`gate/README.md`), so the agent inferred a clean pass from
   `attempts: 1`. `done` should carry the verdict and the artefact paths.
3. **`responds(click)` cannot fail a moving sketch.** `evaluate_assertion` diffs the frame 30 steps
   after the click against the frame before it, so any sketch that passes `motion(idle)` passes it
   with no handler at all. This sketch did respond; the gate could not have known.
   `MEASURE[click-assertion-power]`: gate the same sketch with `mousePressed` removed.
4. **Two instructions disagree.** The rules file's *Verifying* asks the agent to say which parts it
   could not verify; the executor prompt's contract says "nothing else" and forbids claiming tests.
   The agent said nothing. The rules file is an experimental variable, so this is recorded, not fixed.
5. **"Only assert what the prompt asks for"** reads oddly when planner and executor are one agent:
   the prompt named no interaction, the agent designed one and asserted it. Accepted, with no harm.
6. **`--executor` with the agent's own id** was accepted and ran as one session. Worth one line in
   AGENTS.md so the next agent does not wonder whether it should have handed off.

## 10. Caveats

One run, one agent, at effort `max`, given an unusually craft-heavy skill and a one-off prompt. Nothing
here is a rate. The node's own record for entry 1279 (`wall_s`, the gate's `ms_per_frame`, the strip)
was not read by the agent, on the instruction not to look at the node; the operator can read it off the
entry page and `report.json`, and §5.4 asks for the comparison. The write-up turn that produced this
dossier ran at the same setting and generated about 76,000 tokens, 68,000 of them thinking, before
this file was written, on a rig that was already staged. The effort setting is a suspect, not a
finding.

## Appendix: `cost.py`

The meter behind §2 and §6.3. It was run against this session and reproduces every figure above:
the pre-start window gives 59 messages, 109 tool calls, 16 screenshots and 192,739 tokens (148,845
thinking), the job window 11 messages, 13 tool calls and 14,798 tokens, and an empty window exits 1.
Meant to become `rig/cost.py`.

```python
#!/usr/bin/env python3
"""cost.py: what this session has cost so far, from the transcript Claude Code already writes.

    python3 cost.py [--since ISO] [--until ISO] [--transcript PATH]

Every assistant message in the transcript carries its own `usage` and a timestamp, so
time, tokens generated, thinking, tool calls and screenshots can be totalled at any
moment, by the agent or by the operator, with nothing installed. It reads the newest
transcript for the current directory unless told which one. Prints a summary and, last,
one JSON line to paste into a packet's `process`. Stdlib only.
"""
import argparse, collections, glob, json, os, re, sys
from datetime import datetime

def when(ts):
    return datetime.fromisoformat(ts.replace("Z", "+00:00"))

def newest_transcript():
    slug = re.sub(r"[^A-Za-z0-9]", "-", os.getcwd())
    files = glob.glob(os.path.expanduser(f"~/.claude/projects/{slug}/*.jsonl"))
    return max(files, key=os.path.getmtime) if files else None

def main():
    ap = argparse.ArgumentParser(description=__doc__.split("\n")[0])
    ap.add_argument("--since"); ap.add_argument("--until"); ap.add_argument("--transcript")
    a = ap.parse_args()
    path = a.transcript or newest_transcript()
    if not path:
        sys.exit("no transcript found for this directory")
    lo = when(a.since) if a.since else None
    hi = when(a.until) if a.until else None

    msgs, tools, shots, stamps = {}, set(), 0, []
    for line in open(path):
        try:
            r = json.loads(line)
        except ValueError:
            continue
        ts, m = r.get("timestamp"), r.get("message")
        if not ts or not isinstance(m, dict):
            continue
        t = when(ts)
        if (lo and t < lo) or (hi and t > hi):
            continue
        stamps.append(t)
        blocks = m.get("content") if isinstance(m.get("content"), list) else []
        if r.get("type") == "assistant" and m.get("usage"):
            # A message can span several lines with the same id: keep the largest of each count.
            d = msgs.setdefault(m.get("id") or r.get("uuid"), collections.Counter())
            u = m["usage"]
            for k, v in (("out", u.get("output_tokens")), ("think", (u.get("output_tokens_details") or {}).get("thinking_tokens"))):
                d[k] = max(d[k], v or 0)
            tools.update(b["id"] for b in blocks if isinstance(b, dict) and b.get("type") == "tool_use")
        if r.get("type") == "user":
            for b in blocks:
                if isinstance(b, dict) and b.get("type") == "tool_result" and isinstance(b.get("content"), list):
                    shots += sum(1 for x in b["content"] if isinstance(x, dict) and x.get("type") == "image")

    if not stamps:
        sys.exit("nothing in that window")
    start = lo or min(stamps)
    end = hi or max(stamps)
    out = sum(d["out"] for d in msgs.values())
    think = sum(d["think"] for d in msgs.values())
    wall = int((end - start).total_seconds())
    print(f"{start:%H:%M:%SZ} -> {end:%H:%M:%SZ}  {wall // 60} min {wall % 60} s")
    print(f"{len(msgs)} assistant messages, {len(tools)} tool calls, {shots} screenshots")
    print(f"{out:,} tokens generated, {think:,} of them thinking ({100 * think // max(out, 1)}%)")
    print(json.dumps({"session_s": wall, "output_tokens": out, "thinking_tokens": think,
                      "tool_calls": len(tools), "screenshots": shots}))

if __name__ == "__main__":
    main()
```
